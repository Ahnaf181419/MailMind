# 07 — UI Screens

Five screens, all server-rendered shells with client interactivity. Every screen must work at 1280×800 (judge laptop) and gracefully scale down to 1024 wide.

## Visual system

| Token | Value |
|---|---|
| Font (UI) | Inter (variable) |
| Font (mono) | JetBrains Mono |
| Primary | `slate-900` on light, `slate-50` on dark |
| Accent (urgent) | `#dc2626` (red-600) |
| Accent (stale) | `#ea580c` (orange-600) |
| Accent (action) | `#2563eb` (blue-600) |
| Accent (success) | `#16a34a` (green-600) |
| Background | `slate-50` |
| Card | white with `border-slate-200` |
| Radius | `rounded-xl` cards, `rounded-md` buttons |
| Shadow | `shadow-sm` default, `shadow-md` on hover |

A small, restrained icon set from `lucide-react`. No emojis in UI text. Colour use is functional, not decorative.

## Component primitives (shadcn/ui)

- `Button` (default, ghost, destructive)
- `Card`, `CardHeader`, `CardContent`
- `Badge` (with colour variants for priority)
- `Avatar`, `Dropdown`
- `Dialog` (for draft reply modal)
- `Tabs` (for category views)
- `Toast` (for status update confirmations)
- `Skeleton` (loading states)

No custom design system needed.

## Accessibility

- Keyboard navigable (tab order, focus rings)
- ARIA labels on icon-only buttons
- Color is never the sole signal (text + icon accompany priority colours)
- High contrast on text/backgrounds (WCAG AA)
- Screen-reader friendly summary text

## Performance

- React Query caches `/api/dashboard` for 30s
- Email lists paginated to 20 per page
- All images via Next.js `<Image>`
- No heavy client JS — server-rendered shells
